구현커밋 진단 구조도

이번 구현은 run-all이 조용히 멈췄을 때 “왜 멈췄는지 알 수 없는 상태”를 “어디를 보면 되는지 남는 상태”로 바꾼 작업입니다.

입력

plan-first 문서

plan-first(계획을 먼저 문서로 잠그는 방식) 문서를 받아 commit unit으로 쪼갭니다.

→
정리

queue unit

queue unit(작업 하나의 상태 데이터)에 수정 가능 경로와 필요한 스킬을 보존합니다.

→
실행

Codex child process

child process(구현커밋이 따로 실행하는 Codex 작업)가 실제 구현과 리뷰를 수행합니다.

스킬 보존

Skill Routing Manifest

Skill Routing Manifest(작업별로 꼭 읽어야 할 스킬 표)를 source plan에서 queue와 generated plan까지 유지합니다.

경로 분리

allowed / external paths

allowed_paths(현재 repo 안에서 자동 수정 가능한 경로)와 external_allowed_paths(repo 밖이라 자동 수정하면 위험한 경로)를 나눕니다.

프롬프트 축소

scoped dirty status

dirty status(아직 커밋되지 않은 변경 목록)는 allowed path 안쪽만 자세히 보여주고, 나머지는 개수만 보여줍니다.

제한

timeout

timeout(너무 오래 걸리면 끊는 시간 제한)을 기본 900초로 두고 --codex-timeout-seconds로 바꿀 수 있게 했습니다.

멈춤

needs_work

needs_work(사람이나 다음 실행이 다시 봐야 하는 상태)로 unit을 멈추고 다음 unit으로 넘어가지 않습니다.

증거

diagnostic_path

diagnostic_path(실패 증거 파일 위치)에 prompt.md, stdout.log, stderr.log, metadata.json 등을 남깁니다.
