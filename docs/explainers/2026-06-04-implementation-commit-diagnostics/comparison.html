구현 전후 비교

이번 변경은 “기능을 더 많이 돌리는 것”보다 “실패했을 때 어디를 봐야 하는지 남기는 것”에 초점이 있습니다.

비교 기준 이전 상태 이후 상태
멈춤 대응 불명확
자식 Codex가 조용히 오래 걸리면 사용자는 멈춘 건지 기다려야 하는지 알기 어려웠습니다.		 명확
timeout(시간 제한)을 두고, 넘으면 unit을 needs_work(다시 봐야 하는 상태)로 바꿉니다.
실패 증거 부족
실패 당시 prompt, stdout, stderr가 plan 폴더에 안정적으로 남지 않았습니다.		 보존
diagnostic_path(실패 증거 위치)에 prompt.md, stdout.log, stderr.log, metadata.json을 남깁니다.
스킬 라우팅 흐려짐
source plan의 specialist skill이 generated queue에서 기본값으로 바뀔 수 있었습니다.		 보존
Skill Routing Manifest(작업별 필수 스킬 표)를 queue와 generated plan에 유지합니다.
수정 경로 위험
repo 밖 절대 경로가 자동 수정 가능 경로처럼 섞일 수 있었습니다.		 분리
allowed_paths(repo 안 자동 수정 경로)와 external_allowed_paths(repo 밖 확인 필요 경로)를 나눕니다.
프롬프트 노이즈 많음
dirty file 전체가 구현 프롬프트에 들어가 unrelated 파일명까지 보일 수 있었습니다.		 축소
allowed path 안쪽만 자세히 보여주고 나머지는 “몇 개 숨김”으로 표시합니다.

한 줄로 말하면, 이제 구현커밋은 실패를 숨기지 않고 “멈춘 위치와 증거 파일”을 남깁니다.
