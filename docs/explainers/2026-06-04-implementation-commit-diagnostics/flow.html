run-all은 이제 이렇게 움직입니다

아래 흐름은 사용자가 run-all --auto-resolve를 실행했을 때 구현커밋이 어떤 순서로 판단하는지 보여줍니다.

1

plan-first 문서 읽기

plan-first(계획을 먼저 잠그는 방식) 문서에서 commit unit과 필요한 스킬 표를 읽습니다.

2

작업 범위 정리

allowed_paths(자동 수정 가능한 repo 안 경로)만 구현 대상에 넣고, repo 밖 경로는 external_allowed_paths(사람 확인이 필요한 외부 경로)로 분리합니다.

3

Codex child process 실행

child process(구현커밋이 따로 실행하는 Codex 작업)가 implementation과 review를 수행합니다. 기본 제한 시간은 900초입니다.

성공하면

review gate를 통과하고 변경 파일을 커밋합니다. 이후 다음 unit으로 넘어갈 수 있습니다.

timeout 또는 실패하면

needs_work(다시 봐야 하는 상태)로 멈춥니다. 다음 unit으로 넘어가지 않고 diagnostic_path(실패 증거 위치)를 남깁니다.

4

나중에 다시 볼 수 있음

diagnostic_path 아래에서 prompt.md, args.json, stdout.log, stderr.log, metadata.json을 열어 원인을 확인합니다.
