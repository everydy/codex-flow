구현커밋 진단 개선 미니 슬라이드

이 파일은 이번 구현을 발표 자료처럼 빠르게 넘겨 보는 용도입니다.

1. 문제

run-all이 멈춘 것처럼 보였다

진짜 문제는 “오래 걸렸다”가 아니라, 오래 걸릴 때 어디서 왜 멈췄는지 증거가 남지 않았다는 점이었습니다.

2. 해결 방향

실패를 관측 가능한 상태로 바꿈

timeout(시간 제한), needs_work(다시 봐야 하는 상태), diagnostic_path(실패 증거 위치)를 연결했습니다.

3. 실행 증거

이제 파일이 남는다

실패하면 prompt.md, args.json, stdout.log, stderr.log, last-message.txt, metadata.json을 볼 수 있습니다.

4. 계획 정합성

source plan의 의도를 보존

Skill Routing Manifest(작업별 필수 스킬 표)를 queue와 generated plan에 유지해서 실행자가 엉뚱한 스킬로 가지 않게 했습니다.

5. 안전장치

수정 범위를 더 좁게 봄

allowed_paths(repo 안 자동 수정 경로)와 external_allowed_paths(repo 밖 확인 필요 경로)를 나눴고, dirty status도 필요한 범위만 보여줍니다.

6. 검증

90개 테스트 통과

최종 검증은 python3 -m pytest였고 결과는 90 passed였습니다.

timeout/failure 진단 파일 테스트
source manifest 보존 테스트
allowed/external path 분리 테스트
